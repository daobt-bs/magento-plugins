# Magento 2 security rules (OWASP Top 10:2025)

Apply these rules whenever you write or modify Magento 2 code, together with the general rules in `general-rules.md` (including its "How you work" section). They are grouped by what you are writing; each group names the weakness classes (CWE) it prevents. Rule IDs match the developer document `../docs/owasp-rules-m2.md`; open it for the reasoning and full examples behind any rule. Class names were checked against Magento 2.4.6-p4; APIs that need a later version are marked.

These rules exist because the listed patterns have caused real vulnerabilities in Magento projects. If a task seems to require breaking a rule, stop and tell the user which rule and why instead of working around it.

Sources: OWASP Top 10:2025 and OWASP Cheat Sheet Series (CC BY-SA 4.0), paraphrased; Magento API names from the 2.4.6-p4 source. Details per topic: https://cheatsheetseries.owasp.org/cheatsheets/<Name>_Cheat_Sheet.html, names given in each `Ref:` line.

## Admin controllers and UI components (CWE-862, CWE-285)
- M2-A01-01 Declare `public const ADMIN_RESOURCE = 'Vendor_Module::action'` in every admin controller and declare that resource in `etc/acl.xml`. The inherited default `Magento_Backend::admin` lets every admin role in.
- M2-A01-02 Extend `Magento\Backend\App\Action`. Admin login and URL secret-key checks are attached to that class; a controller extending `Magento\Framework\App\Action\Action` skips them.
- M2-A01-06 Actions that create, update or delete implement `HttpPostActionInterface`.
- M2-A01-08 Every admin UI component `<dataSource>` declares `<aclResource>Vendor_Module::resource</aclResource>`. Its data is reachable through `mui/index/render` without passing your controller.

## Frontend controllers, REST services and GraphQL resolvers (CWE-639, CWE-352, CWE-915)
- M2-A01-10 Frontend controllers for logged-in customers implement `Magento\Customer\Controller\AccountInterface` (its plugin forces login). Its exemption list matches by action name only (`create`, `login`, `confirm`, `createpost`, `forgotpassword`, `resetpassword`, …) in every module, so do not name such actions that way, or also check `isLoggedIn()`. Mark intentionally public frontend controllers (signed webhooks) with a code-level marker the team can grep (e.g. an empty marker interface or a list in `di.xml`), not only a comment.
- M2-A01-05 After loading an entity by an ID from the request, verify it belongs to the current customer (`$customerSession->getCustomerId()`); for orders on customer-account pages use `OrderViewAuthorizationInterface::canView()` (it is false for guests and, by default config, for `pending_payment`; on checkout return pages take the order from `CheckoutSession::getLastRealOrder()` and require the URL parameter to match its increment ID). Wrap `orderRepository->get()` and turn `NoSuchEntityException` and `InputException` (empty ID) into not found. On mismatch respond as not found. Apply the same check in every entry point to that data: controller, REST service (`UserContextInterface`), GraphQL resolver (query context).
- M2-A01-06 (frontend, continued) State-changing actions implement `HttpPostActionInterface` and rely on the form key. Do not implement `CsrfAwareActionInterface::validateForCsrf()` returning `true`, except for a webhook that verifies a signature (M2-A08-03).
- M2-A06-01 Never take price, discount, totals or customer ID from the request. Request carries identifiers and quantity only; compute the rest server-side. Cast and range-check numbers.
- M2-A06-02 A public (no-login) action that sends email or writes to the database needs reCAPTCHA/Captcha or another throttle, on every entry point (controller, REST, GraphQL). Magento 2.4.6 has no generic rate limiter for custom controllers. OWASP gives no numbers; use core defaults as a baseline unless the user specifies (customer login 10 failures → 10 min lock, admin 6 → 30 min, password reset 5/hour and 10 min apart, send-to-friend 5/hour). For reCAPTCHA on a custom controller write a `controller_action_predispatch_<route>` observer using `ReCaptchaUi\Model\IsCaptchaEnabledInterface` and `RequestHandlerInterface` (core observers need `getResponse()` on the controller).
- M2-A06-03 Cap list and bulk input: clamp page size and array length from the request to a constant maximum. Move heavy work to a queue or cron: outbound calls in a loop, more than one email, file or image processing/generation, unbounded collection walks, anything that may exceed the caller's timeout.
- M2-A08-02 Never pass `getParams()` / `getPostValue()` straight into `setData()` / `addData()`. Set each allowed field explicitly; take ownership fields from the session.
- M2-A07-03 Failure messages must not reveal whether an email or account exists.
- M2-A01-09 Redirects use `$resultRedirect->setRefererOrBaseUrl()` or `$this->_redirect->success()` / `getRefererUrl()`, which fall back to the store base URL for foreign hosts. Never `setUrl()` with a request value. These helpers accept internal targets chosen via the Referer header and the `referer_url`, `uenc`, `r64`, `success_url`, `error_url` parameters; that is acceptable (internal only). For a fixed target prefer `setPath()`. `HostChecker::isOwnOrigin()` treats a URL without host as internal; do not use it alone on user input.
- M2-A06-04 Check-then-write on custom coupon, stock, points or balance tables: `$connection->update($table, $bind, ['id = ?' => $id, 'used = ?' => 0])` and require exactly 1 affected row, or `$select->forUpdate(true)` inside `beginTransaction()`; cross-process: `LockManagerInterface::lock()` / `unlock()`; one-per-customer: unique index in `db_schema.xml` (via a resource model the duplicate surfaces as `AlreadyExistsException`, not `DuplicateException`; for raw inserts use `insertArray(..., AdapterInterface::INSERT_IGNORE)` and check the row count). For a decrement, `forUpdate` the row, compute in PHP, and update with the old value in the WHERE (exactly 1 row), or use `new \Zend_Db_Expr($connection->quoteInto('balance - ?', $amount))` with `balance >= ?` in the WHERE.
- M2-A06-04 (continued) Per-user or per-period limits ("max N per day") are check-then-write too: hold `LockManagerInterface::lock('<module>_<action>_' . $customerId, 5)` around count + save (unlock in `finally`, refuse with 429 if the lock is busy), or keep a counter row per (user, period) incremented by a conditional update `count < N`.
- M2-A06-02 (continued) Features that email a request-supplied address (send to friend, share, gifts) need per-account limits even when logged in (count per customer ID; core SendFriend defaults to 5 recipients and 5 per hour but counts per cookie, which core itself labels unsafe); validate the address with `Validator\EmailAddress` and reject CR/LF.
Ref: Authorization, IDOR Prevention, Unvalidated Redirects and Forwards, Business Logic Security, Mass Assignment

## `etc/webapi.xml` (CWE-862, CWE-639)
- M2-A01-03 Do not use `<resource ref="anonymous"/>` unless the endpoint is intentionally public and exposes no customer, order or internal data. Use an ACL resource. Never commit test routes.
- M2-A01-03 (integrations) One ACL resource per endpoint group; grant integrations only what they need. ACL grants by resource type, not by record: if partners must only see their own data, check `UserContextInterface::getUserType() === USER_TYPE_INTEGRATION`, map `getUserId()` to the partner server-side and filter by it; never trust a partner ID from the request. Leave `oauth/consumer/enable_integration_as_bearer` off (default) unless a partner cannot sign OAuth 1.0a. No keys or tokens in URLs.
- M2-A01-04 Customer endpoints use `<resource ref="self"/>` together with `<parameter name="customerId" force="true">%customer_id%</parameter>`.

## Templates (`.phtml`), UI components and JavaScript (CWE-79)
- M2-A05-02 Escape every dynamic output by context: `$escaper->escapeHtml()` for HTML text, `escapeHtmlAttr()` for attributes, `escapeUrl()` for href/src, `escapeJs()` inside JS strings, `escapeCss()` in CSS. Skip escaping only for HTML produced by code (`getChildHtml()`, `toHtml()`, methods ending in `Html`) and mark it `/* @noEscape */`. Do not escape twice.
- M2-A05-03 Use `$block` and `$escaper`, never `$this`. Pass PHP data to JS as JSON from `Magento\Framework\Serialize\Serializer\Json`, not by string concatenation; when the data contains user input and is printed inside `<script>`, use `Serializer\JsonHexTag` (`getJsLayout()` uses plain `json_encode`); user-entered values in `jsLayout` config also need `'__disableTmpl'`. Provider `data` and form element `value` are excluded from `${ }` templating automatically in 2.4.6, but labels, `options`, `actions` and `imports` are not: add `'__disableTmpl' => true` to any of them built from stored user input. In JS, insert server data with `.text()` / `textContent`, not `.html()` / `innerHTML`. In Knockout use the `text` binding, not `html`. 
- M2-A02-03 Render inline scripts with `$secureRenderer->renderTag('script', [], $js, false)` and event handlers with `renderEventListenerAsTag()`; no `onclick="..."` attributes. Declare external domains in the `etc/csp_whitelist.xml` of the module that needs them. `CspNonceProvider` exists only from 2.4.7. `<script type="text/x-magento-init">` holds JSON, not executable JS: write it directly (no `renderTag()` needed) but serialize its data per M2-A05-03.
- M2-A08-04 Self-host third-party scripts; if a CDN is unavoidable add `integrity` and `crossorigin`.
- M2-A04-05 (notes) Forms on cached pages use the normal form key block; core JS refreshes it from a cookie, so no `no-store` is needed. Redirects carrying session messages need no extra headers (FPC caches only 200/404).
- M2-A04-05 Never render customer-specific data (name, cart, address, customer price) in a block on a cacheable page: full page cache stores it and serves it to other visitors. Use customer-data sections (`SectionSourceInterface`, registered in `sectionSourceMap` of `SectionPoolInterface` in `etc/frontend/di.xml`, and invalidated for every changing action in `etc/frontend/sections.xml`) rendered in JS — widgets and CMS blocks included — or `cacheable="false"` only on customer-only pages (it disables FPC for the whole page). Controllers returning private JSON or files call `$this->getResponse()->setNoCacheHeaders()` (controllers without `getResponse()` set `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` on the result object); never `setPublicHeaders()` on them.
- M2-A05-06 In email templates `{{var x}}` escapes only when it has no modifier: any modifier replaces the default (`{{var x|nl2br}}` and `{{var x|raw}}` are unescaped). For customer data the first modifier is always `escape` (`{{var x|escape|nl2br}}`). Never run customer-entered text through a template filter (`Magento\Email\Model\Template\Filter`, `FilterProvider::getBlockFilter()` / `getPageFilter()`); pass it as a template variable instead. Do not let the request choose a template ID or `.phtml` path.
- M2-A05-07 Build absolute URLs with `UrlInterface::getUrl()` or the store `getBaseUrl()`, never with `getHttpHost()` / `HTTP_HOST` / `X-Forwarded-Host` (and note a `{{base_url}}` placeholder in config is itself filled from the request; tell the user if you see it). Do not put request values into `setHeader()` unvalidated.
- M2-A02-04 Set cookies through `CookieManagerInterface`: private values with `setSensitiveCookie()` and `createSensitiveCookieMetadata([CookieMetadata::KEY_DURATION => $seconds])` (HttpOnly and SameSite=Lax by default; it has no `setDuration()`); never `setcookie()`. Never store tokens in `localStorage`.
Ref: Cross Site Scripting Prevention, Server Side Template Injection Prevention, Input Validation, Web Cache Security, Session Management

## Database access (CWE-89)
- M2-A05-01 Never interpolate or concatenate variables into SQL. Prefer repositories and collections; otherwise `$connection->select()->where('col = ?', $value)` and `insert/update/delete` with bind arrays. Column or table names coming from input must be matched against a fixed allow-list.
- M2-A10-03 Wrap writes that span several tables or models in `beginTransaction()` / `commit()` with `rollBack()` in the catch. Call external APIs after commit; work that must not be lost (emails after money moves, ERP sync) goes into a module outbox table written in the same transaction and sent by cron that claims rows with a conditional update.
- M2-A10-04 `$factory->create()->load($id)` always returns an object. Check `getId()`, or use a repository `getById()` which throws `NoSuchEntityException`.
Ref: SQL Injection Prevention, Business Logic Security, Error Handling

## Files, uploads and system commands (CWE-434, CWE-22, CWE-78, CWE-94)
- M2-A05-05 Uploads: `setAllowedExtensions([...])` with a fixed, non-empty allow-list in code (an empty array allows every extension; never php, phtml, phar, svg, html, js); admin config may only narrow it. `MediaStorage\Model\File\Validator\Image::isValid()` returns true for non-image MIME types, so never rely on it alone: check with `getimagesize()` (also cap pixel dimensions), then re-encode via `Framework\Image\AdapterFactory` open/save. Serve uploaded files with `nosniff` and a fixed `Content-Type`. Uploads that become public only after moderation stay in `var/` behind a controller that checks the approval status. If unsure the web root is `pub/`, tell the user. Get the extension with `getFileExtension()` before `save()` (`getUploadedFileName()` is null until after `save()`). Check the size from the request files before `save()` (Uploader has no size limit); delete files that fail validation. Files from SFTP/drop folders: allow-list the name by regex, cap the size before reading, skip files still being written, move to `processed/` or `failed/`. `var/` is private only if the web root is `pub/`. Store under a random name from `Math\Random`, never the client filename; do not trust the client `Content-Type`. Private files (attachments, documents) go under `var/`, not `pub/media`, and are downloaded through a controller that checks ownership. Read, write and delete through `Magento\Framework\Filesystem\Directory\WriteInterface`. Resolve files from a database record ID, never from a filename or path in the request.
- M2-A05-04 No `exec`, `shell_exec`, `system`, `passthru`, `popen`, `proc_open`, `eval`, or `include`/`require` with a variable path. If an external command is unavoidable use `Magento\Framework\Shell::execute('cmd %s', [$arg])`.
- M2-A02-01 Do not add standalone PHP scripts, database tools, dumps or archives to the project root or `pub/`. One-off jobs become console commands or data patches.
- M2-A09-03 No `var_dump`, `print_r`, `die`, `exit`, or `file_put_contents` debug logs; nothing written under `pub/` for debugging.
- M2-A02-05 Imported XML (ERP files, feeds): reject any document with a DOCTYPE, checked after parsing (`$dom->doctype !== null`), not by string search; never pass `LIBXML_NOENT`, `LIBXML_DTDLOAD` or `LIBXML_DTDVALID`; to block entity loading install `libxml_set_external_entity_loader(function () { return null; })` just before parsing a string (`loadXML`; with the loader installed `DOMDocument::load($file)` fails) and restore it with `libxml_set_external_entity_loader(null)` in `finally`, since it is process-wide; call `libxml_clear_errors()` first. `Magento\Framework\Xml\Security::scan()` can reject `<!ENTITY` as an extra layer (under PHP-FPM it is only a `<!ENTITY` string check that UTF-16 input bypasses).
Ref: File Upload, Path Traversal Prevention, XML External Entity Prevention, OS Command Injection Defense

## Outbound HTTP and integrations (CWE-918, CWE-295, CWE-345)
- M2-A01-07 Never build a request URL from user input. Host comes from admin config (validate it is a bare host name); paths come from a fixed map keyed by an allow-listed parameter; a variable ID segment is regex-checked and `rawurlencode`d. `Magento\Framework\HTTP\Client\Curl` defaults to a 300 s timeout and allows FTP: call `setTimeout(10)` and set `CURLOPT_CONNECTTIMEOUT`, `CURLOPT_PROTOCOLS => CURLPROTO_HTTPS`, `CURLOPT_FOLLOWLOCATION => false`, `CURLOPT_MAXREDIRS => 0`; it throws a generic `\Exception`, so catch that around the call only. Do not return the remote response in error messages. Cap the response size: `CURLOPT_MAXFILESIZE` is not enough (responses without Content-Length are not stopped); set `CURLOPT_NOPROGRESS => false` and `CURLOPT_XFERINFOFUNCTION => static fn($ch, $t, $now) => $now > MAX_BYTES ? 1 : 0` (the client then throws).
- M2-A04-04 Never set `CURLOPT_SSL_VERIFYPEER` / `CURLOPT_SSL_VERIFYHOST` to false or `'verify' => false`.
- M2-A08-03 Webhook endpoints verify an HMAC signature over the raw body with `hash_hmac('sha256', ...)` and `Magento\Framework\Encryption\Helper\Security::compareStrings()` before doing anything; return 401 with a generic body (no reason) on failure. Store processed event or transaction IDs under a unique index, in the same transaction as the business change, and return 200 without re-running side effects on repeats; reject stale signed timestamps when the sender provides them (5 minutes is a common default). Status: 401 generic body for bad signature (log it: time, IP, event ID, type; never the body, secret or signature header), 400/413 malformed or oversized, 429 with Retry-After when you cannot process yet (lock busy), 200 only after it is stored or processed (also for ignored valid events).
- M2-A06-05 Payment modules: the return-URL controller never invoices or changes order state from URL parameters. Before fulfilling, verify the transaction through the gateway API and match amount and currency with `$order->getGrandTotal()` and `$order->getOrderCurrencyCode()` and the order ID. Bind the gateway transaction to the order by storing its ID on the payment at redirect time, and require later notifications to match it (mismatch: no invoice, set `payment_review`, alert). Compare money as integers in minor units, in the currency you actually sent (order: `getGrandTotal()`/`getOrderCurrencyCode()`; base: `getBaseGrandTotal()`/`getBaseCurrencyCode()`). Invoice once: check `$order->canInvoice()` and whether the transaction ID is already stored (`getByTransactionId()` exists on the concrete `Order\Payment\Transaction\Repository`, not on the interface). Lock per order with `LockManagerInterface::lock($name, 15)` — with the default DB backend a timeout of -1 waits up to one week — check the boolean result (busy: answer 429 with Retry-After), and `unlock()` in `finally`. `getByTransactionId()` searches one payment only; to stop a transaction ID being reused on another order, keep processed IDs in a module table with a unique index. Never invoice or change order state on the GET return page; restore the quote on cancel only in a separate POST.
- M2-A09-02 Do not log raw request/response bodies or headers. Never log passwords, tokens, session IDs, API keys, authorization headers or card data.
Ref: Server Side Request Forgery Prevention, Webhook Security, Third Party Payment Gateway Integration, Logging

## Secrets, crypto and randomness (CWE-798, CWE-327, CWE-338)
- M2-A07-02 No credentials, API keys or tokens in code, XML defaults or data patches. Do not create admin or customer accounts with fixed passwords in patches.
- M2-A04-03 Secret config fields use `type="obscure"` with `<backend_model>Magento\Config\Model\Config\Backend\Encrypted</backend_model>`; read with `EncryptorInterface::decrypt()`. Never expose the decrypted value to the frontend or logs. Also declare each secret path as sensitive in `etc/di.xml` (`Magento\Config\Model\Config\TypePool`, argument `sensitive`, item `<path>` = `1`) so `app:config:dump` writes it to `env.php`, not the committed `config.php`.
- M2-A04-01 No `md5` / `sha1` (including `hash('md5'|'sha1', …)`) for passwords, tokens or signatures. Bearer values in custom tables (gift card codes, secret coupons, partner tokens): store a SHA-256 hash with a unique index; encrypt with `EncryptorInterface` only when the plaintext must be recovered, and clear it after use. Passwords: `EncryptorInterface::getHash($password, true)` / `isValidHash()`. Signatures: `hash_hmac('sha256', ...)`. Compare secrets with `Security::compareStrings()`, not `===`.
- M2-A04-02 Security-relevant random values come from `Magento\Framework\Math\Random::getRandomString()` / `getUniqueHash()` or `random_int()`. Not `rand`, `mt_rand`, `uniqid`. Tokens and secrets are at least 16 characters, preferably 32.
- M2-A02-02 Never commit `app/etc/env.php` or `auth.json`. No `ini_set('display_errors', ...)` or `error_reporting(...)` in module code.
- M2-AI-05 Do not open or print `app/etc/env.php` (database credentials and the `crypt` key), `auth.json` or database dumps.
Ref: Password Storage, Cryptographic Storage, Secrets Management, Secure Coding with AI

## Authentication (CWE-287)
- M2-A07-01 Do not write custom login, session or password-reset logic. Use `Magento\Customer\Api\AccountManagementInterface` (`authenticate()`, `initiatePasswordReset()`). Any use of `setCustomerAsLoggedIn`, `setCustomerDataAsLoggedIn` or `loginById` without a verified credential must be flagged to the user for security review.
- M2-A07-04 Log a customer in only through `$customerSession->setCustomerDataAsLoggedIn()` (it regenerates the session ID), never `setCustomerId()`. Password changes go through `AccountManagementInterface::changePassword($email, $currentPassword, $newPassword)`.
- M2-A07-05 (if you verify JWTs yourself) Call `JwtManagerInterface::read($token, [$theOneAlgorithmYouIssue])`, never include `Jwt\Unsecured\NoEncryption` or a key with algorithm `none` in that list (that accepts unsigned tokens), build HS256 keys with `JwkFactory::createHs256($secret)`, and then check `exp`, `iss` and `aud` yourself.
Ref: Authentication, Session Management, Forgot Password, JSON Web Token

## Serialization (CWE-502)
- M2-A08-01 Never call PHP `unserialize()` / `serialize()`. Use `Magento\Framework\Serialize\Serializer\Json`.

## Error handling and logging (CWE-209, CWE-390, CWE-532, CWE-117)
- M2-A10-01 No empty `catch` blocks and no `@` error suppression. Catch only what you handle; otherwise log and rethrow. Cron/consumer loops may catch `\Exception` per item, log, mark the item failed and continue. Always write `\Exception` with the leading backslash (or import it) in namespaced files.
- M2-A10-02 Only `LocalizedException` messages may be shown to users. For any other exception, log it with `$logger->critical($e)` and return a generic message.
- M2-A09-01 Log denied access, input validation failures, admin user and privilege changes, imports/exports, uploads, invalid signatures and bulk admin actions through `Psr\Log\LoggerInterface`. Put variable data in the context array, not in the message string. Take the IP from `RemoteAddress::getRemoteAddress()`; it honours forwarded headers only if `alternativeHeaders` is configured, and without `trustedProxies` it then takes the leftmost (client-controlled) IP, so configure both, and only behind your own proxy.
Ref: Logging, Error Handling, Input Validation

## Dependencies
- M2-A03-01 Add third-party libraries through composer. Never copy library source into a module.
- M2-A03-02 Never edit files under `vendor/`. Change behaviour with a plugin, preference or a composer patch. Mention any `composer.json` change to the user.
- M2-A03-01 (continued) Before proposing a package, confirm it exists on Packagist or repo.magento.com under that exact name. Do not invent package names or versions.

## Tests
- When you change authorization, pricing, upload or webhook code, add at least one negative test: another customer's record, a role without the ACL resource, a forbidden file extension, an invalid signature.

## Self-check before reporting the work as done
Do this in two passes. First, re-read your diff against the groups above and list every place where a rule might be broken. Second, fix what you found and re-read once more. Then run these against the module you touched and review every hit; a hit is a candidate, not automatically a violation.

```bash
M=app/code/Vendor/Module
vendor/bin/phpcs --standard=Magento2 --sniffs=Magento2.Security.XssTemplate,Magento2.Security.InsecureFunction,Magento2.Security.Superglobal,Magento2.Security.IncludeFile,Magento2.Security.LanguageConstruct $M
grep -rL "ADMIN_RESOURCE\|_isAllowed" $M/Controller/Adminhtml --include=*.php
grep -rn 'ref="anonymous"' $M --include=webapi.xml
grep -rL "aclResource" $M/view/adminhtml/ui_component --include=*.xml
grep -rn "validateForCsrf\|SSL_VERIFYPEER\|SSL_VERIFYHOST" $M
grep -rnE "(fetchAll|fetchOne|fetchRow|fetchCol|query)\(\s*[\"'].*(\\$|\{)" $M --include=*.php
grep -rnE "(setData|addData)\(.*(getParams|getPostValue)\(\)" $M --include=*.php
grep -rnE "\b(md5|sha1|mt_rand|rand|uniqid|var_dump|print_r)\(|hash\(\s*['\"](md5|sha1)|[^>:a-zA-Z_]unserialize\(" $M --include=*.php
grep -rnoE '\{\{var [^}]*\|[^}]*\}\}' $M/view/*/email 2>/dev/null | grep -vE '\{\{var [^}|]*\|escape'
grep -rnE 'NoEncryption|ALGORITHM_NONE' $M --include=*.php
grep -q 'Backend\\Encrypted' $M/etc/adminhtml/system.xml 2>/dev/null && ! grep -q 'TypePool' $M/etc/di.xml 2>/dev/null && echo 'secret config not declared sensitive'
find $M/Controller -not -path '*Adminhtml*' -iregex '.*/\(create\|login\|logoutsuccess\|forgotpassword\|forgotpasswordpost\|resetpassword\|resetpasswordpost\|confirm\|confirmation\|createpassword\|createpost\|loginpost\)\.php' | xargs -r grep -l AccountInterface
grep -rn '\$this->' $M --include=*.phtml
grep -rnE "catch \(Exception |@[a-z_]+\(" $M --include=*.php
grep -rnE 'setUrl\(\s*\$this->(getRequest\(\)|_?request)|getHttpHost\(|HTTP_HOST|setcookie\(|LIBXML_NOENT|LIBXML_DTDLOAD|setPublicHeaders\(' $M
grep -rlPz 'catch\s*\([^)]*\)\s*\{\s*\}' $M --include=*.php
grep -rnE "Zend_Db_Expr\(\s*['\"][^'\"]*['\"]\s*\." $M --include=*.php
grep -rLE 'AccountInterface|isLoggedIn\(' $M/Controller --include=*.php | grep -v Adminhtml
```

If php or phpcs is not available, say so in your summary instead of claiming the check. In your final summary, state which of these you ran and list any rule you knowingly did not follow, with the reason. These rules reduce risk; they do not replace human review of the change.
